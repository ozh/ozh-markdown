# Vendored front end libraries

Everything under `assets/js/vendor/` and `assets/css/vendor/` is generated by
`./tools/fetch-vendor.sh`. Do not hand edit those files: re-run the script and
commit its output.

The script runs on the host, where Node lives. The plugin itself never needs
Node, and the production host never runs a build step.

| Library | Version | Files |
|---|---|---|
| marked | 18.0.10 | `assets/js/vendor/marked.min.js` |
| CodeMirror | 5.65.21 | `assets/js/vendor/codemirror.js`, `assets/js/vendor/codemirror-markdown.js`, `assets/css/vendor/codemirror.css` |
| Prism | 1.30.0 | `assets/js/vendor/prism.js`, `assets/css/vendor/prism.css` |

## Updating a version

Edit the version constants at the top of `tools/fetch-vendor.sh`, run it, then
run `node --test tests/js/*.test.js` before committing. Update the table above.

## The Prism bundle

The bundle is Prism's core concatenated with a fixed language set, rather than
Prism's autoloader, because the autoloader fetches grammars on demand and that
means extra requests and a path dependency at runtime.

Languages, as named in the spec: `markup`, `css`, `clike`, `javascript`, `php`,
`bash`, `sql`, `json`, `yaml`, `diff`, `markdown`, `ini`.

**Dependencies are resolved automatically, and that matters.** `prism-php`
requires `markup-templating`. A bundle without it loads cleanly and then throws
`Cannot read properties of undefined (reading 'buildPlaceholders')` on the first
PHP block. Because that exception escapes `highlightAllUnder()`, it disables
highlighting for *every* language on the page, not just PHP. That shipped once
and reached the browser before it was caught.

`tests/js/prism-bundle.test.js` loads the committed bundle and highlights a
sample of each language, so a missing dependency fails in the test suite rather
than silently in the browser.

To change the language set, edit `PRISM_LANGUAGES` in the script and add a
sample to `SAMPLES` in that test.

## The Prism stylesheet

Light theme (`prism.min.css`) is applied unconditionally, dark
(`prism-tomorrow.min.css`) as a `prefers-color-scheme: dark` override.

Both facts are deliberate. Wrapping the light theme in a
`prefers-color-scheme: light` query leaves a browser reporting no preference
with no highlighting at all. And the upstream themes contain their own
`@media print` block, so wrapping them nests one at-rule inside another, which
is not reliably supported; the script strips that block from the dark theme
before wrapping it.

Neither theme uses `!important`, so an active WordPress theme can override
either.
